# Research and engineering decisions

Reviewed 3 October 2026. These are implementation decisions informed by primary sources, not a claim that this prototype has passed a security audit.

| Area | Do | Avoid | This iteration |
|---|---|---|---|
| [AWS: safe idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) | Bind caller intent to a request key and payload; commit the result atomically | Retrying mutations blindly, or writing a retry receipt after the mutation in a separate transaction | Approval keys are scoped to user/workspace/invoice, payload-bound, and committed with the invoice change; receipts are encrypted and expire after 24 hours |
| [Microsoft Graph throttling](https://learn.microsoft.com/en-us/graph/throttling) and [Gmail errors](https://developers.google.com/workspace/gmail/api/guides/handle-errors) | Bounded retries and provider-directed delays | Immediate retry loops that amplify an outage | Read requests retry transient network/429/5xx failures; Retry-After seconds/dates are respected; long delays persist for the affected access token |
| [Gmail synchronization](https://developers.google.com/workspace/gmail/api/guides/sync) | Full initial capture, then incremental history with recovery when a checkpoint expires | Repeated full-mailbox scans and assuming push notifications are the invoice payload | Existing overlapping polling remains; incremental history and Pub/Sub are the next adapter work |
| [Microsoft message delta](https://learn.microsoft.com/en-us/graph/delta-query-messages) | Track delta per folder and maintain folder coverage | Restricting capture to Inbox when owners file supplier mail into folders | Current queries cover mailbox messages; folder-aware delta/subscriptions remain future work |
| [OWASP file uploads](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) | Validate size/type, sanitize filenames, keep documents private, constrain parsing | Executing invoice instructions/links or publishing uploaded PDFs as static assets | PDF signature and size/page/text limits, authorized encrypted archive, parser child process with time/resource limits; stronger worker-container isolation is still needed for hosting |
| [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) and [tenant isolation](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html) | Resolve the tenant from authenticated membership and check every resource | Trusting a store/workspace ID merely because the client sent it | Query caches, filters, exports, retry receipts, jobs, and documents are workspace-bound; regression checks cover cross-workspace access |
| [W3C modal dialogs](https://www.w3.org/WAI/WCAG22/Techniques/html/H102) | Contain focus while open and return it when closed | Background controls remaining interactive during invoice review | Native dialog review, initial focus, Escape handling and restored focus; unsaved changes are guarded |
| [NN/g progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | Show the main task first, expose secondary detail on demand | Development setup prose and repetitive explanations on customer screens | Document details and line items collapse; concise capture/review/export actions; required privacy and mailbox permission disclosures remain visible |

The responsive navigation also follows [Apple’s sidebar guidance](https://developer.apple.com/design/human-interface-guidelines/sidebars): keep navigation available on large screens and use a compact control where space is limited. SumLine uses a persistent desktop sidebar and a mobile drawer. Its letter-avatar account menu contains the full email and Sign out action; a separate confirmation prevents an accidental session exit.

## Deliberate limits

One app process on one host remains the supported deployment. Database-backed extraction leases improve restart recovery and concurrent job safety; they do not make OAuth sync locks, authentication limits, or SQLite storage a distributed service. Move to PostgreSQL, private object storage, separately managed keys, durable provider checkpoints, and worker isolation before running several API replicas.

Invoice names, amounts and dates remain in encrypted records. New filter/aggregate requests scan that workspace's encrypted archive, then cache an encrypted bounded page and totals. Each invoice/store mutation invalidates the cache. This avoids repeatedly scanning on every dashboard refresh, but uncached query cost remains proportional to the workspace archive. At the intended 4–10 invoices/day this is a reasonable local-test tradeoff; large archives need indexed private search and incrementally maintained aggregates. Cache capacities are 128 query results and 16 exports per workspace.

Mailbox backfills still have page caps (roughly 3,000 candidate messages per check) without a persisted continuation cursor. Very large backlogs require that cursor work before widening deployment. Live provider behavior, OCR, customer identity verification/recovery/MFA, final privacy operator details, and production retention/deletion procedures remain unresolved.
